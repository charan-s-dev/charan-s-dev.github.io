My Game Booking

Turf and sports-venue booking platform

Rosemallow Technologies · product owner and mobile developer (customer and venue-operator apps)

  • 16 pain points
  • 10 customer segments
  • 6 competitors benchmarked
  • 11 revenue streams modelled
  • Flutter
  • BLoC
  • REST APIs
  • Firebase
  • Google Maps
  • Cashfree
  • Razorpay
  • PayU
  • Claude Design
  • Claude Code

Problem

Players hunt for turfs on Google Maps and phone owners to check slots, while owners take bookings by phone, WhatsApp, and walk-in with no single record, so double-bookings happen.

Research

Mapped 16 pain points across 10 customer segments, benchmarked 6 competitors including Zomato's District, and modelled 11 revenue streams and a 5-phase roadmap.

Product

Players find nearby turfs on a map, see live slot availability, pay online, and check in by QR code; owners run bookings, walk-ins, and payouts from a live calendar.

Built with Claude end to end

Claude for research and the PRD, Claude Design for the UI/UX, and Claude Code with personal skills to build both apps and write the automated tests.

MyInvois SME Booster

WhatsApp e-invoicing for Malaysian SMEs

Rosemallow Technologies · full-stack developer and product owner

  • ~10 → 1–2 min per invoice in demos
  • 55 fields per e-invoice on the portal
  • 20 blueprint sections
  • 8 research studies
  • Python
  • FastAPI
  • PostgreSQL
  • WhatsApp Cloud API
  • LHDN MyInvois API
  • Anthropic API
  • Groq
  • Claude Code

Problem

Filling and validating up to 55 fields per e-invoice on LHDN's MyInvois portal takes about 10 minutes at a desk; in recorded demos the bot cuts that to 1–2 minutes from a phone.

Research

Wrote a 20-section product blueprint and 8 research studies, covering intermediary API access, one-scan onboarding, buyer auto-fill, and item classification, plus an audit against LHDN rules.

Product

Sellers create an invoice in WhatsApp by typing, photographing, or speaking in English or Malay, submit it for LHDN validation, and send it to the buyer; saved details make repeat invoices faster. Tested end to end against an LHDN simulator.

Built with Claude end to end

Claude for the blueprint and research, Claude Code for the backend and its automated tests, and Claude inside the bot itself to read free-text invoices.

CineAd

Cloud ad publishing for standalone theatres

Rosemallow Technologies · product researcher and sole Flutter developer

  • 14 pain points mapped
  • 12 research and design docs
  • 10 days to the demo app
  • Flutter
  • Dart
  • BLoC
  • Clean Architecture
  • WebSockets
  • mDNS
  • Dio
  • Android
  • Claude Code

Problem

Theatre ads still travel by pen drive, email, and WhatsApp and are loaded by hand at each screen, so a campaign across 100 theatres is hard to update, track, or prove it ran.

Research

Mapped 14 pain points for agencies, theatres, and advertisers, then specified peak-day scheduling, proof-of-play, and reach reports in the feature spec, information architecture, and user flows.

Product

An Android kiosk plays each screen's ad reel full-screen at showtime, while an operator's phone on the same Wi-Fi finds it automatically to pause, skip, or restart ads with a synced preview.

Built with Claude end to end

Drafted all 12 research and design documents with Claude, then built the demo app in 10 days with Claude Code and personal skills.
